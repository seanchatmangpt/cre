CRE (Common Runtime Environment) is a production-grade YAWL workflow engine built on Erlang/OTP, designed for complex workflow orchestration in cloud-native environments.

KEY FEATURES

36 YAWL Workflow Patterns
Comprehensive workflow pattern library including sequence, parallel split, synchronization, exclusive choice, multi-choice, loops, milestones, critical sections, and multi-instance patterns. Model complex business processes with ease.

Human-in-the-Loop Approvals
Integrate LLM-powered human decisions directly into workflows. Built-in approval workflows with audit trails for compliance and governance.

Fault-Tolerant Execution
Automatic failure recovery and task rescheduling. Mnesia distributed database provides state replication across pods for high availability.

Distributed Scaling
Horizontal pod autoscaling (HPA) based on CPU and custom metrics. Scale across Erlang clusters with automatic load balancing.

OpenTelemetry Observability
Comprehensive observability with structured logging, metrics, and tracing. Native integration with Google Cloud Operations Suite (Logging, Monitoring, Trace).

Web Dashboard
Real-time workflow visualization and monitoring interface. Track workflow execution, view patterns, and debug issues visually.

TECHNICAL HIGHLIGHTS

Built on Erlang/OTP: Leverages 30+ years of telecom-grade reliability. Supports OTP 25-28 with modern performance improvements.

Petri Net Foundation: Formal Petri net model (gen_pnet) ensures deterministic execution and makes workflow state transparent.

Kubernetes-Native: Designed for GKE with StatefulSet, Pod Disruption Budget, and health checks. Supports Spot VMs for cost savings.

Security-First: Pod Security Standards (Restricted), network policies, container image signing, CMEK encryption, and Workload Identity.
